# איפיון: הזמנות alenabepita.co.il בתוך TOP ALENA

**סטטוס:** טיוטה 2 · עודכן 2026-08-17 אחרי החלטות הבעלים
**מטרה:** לנהל הזמנות מהאתר בתוך TOP ALENA — לקבל עם זמן הכנה, לסמן מוכן, יצא, נמסר — מהטלפון ומאייפד במטבח.

---

## 1. מה השתנה מטיוטה 1

טיוטה 1 מיפתה את ההזמנה לשלושת הסטטוסים של WooCommerce. **זה לא מספיק.** הבעלים ביקש מחזור חיים מלא:

> קבלת הזמנה עם **זמן מוערך להכנה** (בחירה מתוך אפשרויות דקות) → **מוכן** → **יצא ללקוח / נאסף** → **השליח מסמן נמסר**

WooCommerce לא יודעת להביע את זה. יש לה `processing` ו-`completed` וזהו. לכן **הסטטוס האמיתי חי אצלנו**, ו-WooCommerce מקבלת ממנו רק את מה שהיא מסוגלת לייצג.

## 2. מחזור החיים

| # | שלב | מי מסמן | מה הלקוח רואה |
|---|---|---|---|
| 1 | **התקבלה** | אוטומטי | ההזמנה התקבלה |
| 2 | **אושרה + זמן הכנה** | מטבח | "מוכן בעוד ~20 דק׳" — **זמן אמיתי, לא הערכה כללית** |
| 3 | **מוכן** | מטבח | מוכן / ממתין לשליח |
| 4 | **יצא ללקוח** (משלוח)<br>**נאסף** (איסוף) | מטבח / שליח | בדרך אליך |
| 5 | **נמסר** | **השליח** | נמסר · תודה |

**שלב 2 הוא הלב.** היום דף התודה מציג טווח קבוע מההגדרות ("40–60 דקות"). מרגע שהמטבח בוחר זמן, **הלקוח רואה את הזמן שהובטח לו בפועל** — וזה ההבדל בין הערכה לבין התחייבות.

### מיפוי חזרה ל-WooCommerce

| הסטטוס שלנו | WooCommerce |
|---|---|
| התקבלה | `pending` / `processing` |
| אושרה, מוכן, יצא, נאסף | `processing` |
| נמסר | `completed` |
| בוטלה | `cancelled` |

WooCommerce נשארת רישום ההזמנה והכסף. **התפעול הוא שלנו.**

## 3. מסך האייפד במטבח

מסך תצוגה קבוע, בסגנון וולט:

- **כרטיסים גדולים**, קריאים ממרחק, בלי גלילה מיותרת
- **מיון לפי דחיפות** — הזמנה שממתינה לאישור ראשונה, אחריה מה שקרוב לזמן שהובטח
- **צליל בהזמנה חדשה**, ומונה זמן שרץ על כל כרטיס
- **כפתור אחד גדול לכל שלב** — לא תפריטים
- **מתעדכן לבד**, בלי לגעת
- **צבע כשחורגים מהזמן שהובטח** — זה מה שהופך את המסך לכלי ולא לרשימה

מצב תצוגה = אותה מערכת, פריסה אחרת. לא אפליקציה שנייה.

## 4. הרשאות

**כל מי שבמשמרת** יכול לקדם הזמנה: לאשר, לסמן מוכן, לסמן יצא.

שתי פעולות נשארות למנהלים בלבד:

- **ביטול הזמנה** — נוגע בכסף ובלקוח
- **שינוי זמן שכבר הובטח** — הבטחה שמשתנה שוב ושוב שווה כלום

**כל פעולה נרשמת עם שם העובד והשעה.** לא כדי לתפוס אף אחד — כדי שכשלקוח מתלונן שההזמנה איחרה, תדע מה קרה ומתי.

**השליח** מקבל תצוגה מצומצמת: ההזמנות שלו בלבד, וכפתור אחד — **נמסר**.

## 5. מודל הנתונים

```prisma
model WooOrder {
  id             String   @id @default(cuid())
  tenantId       String
  wooOrderId     Int
  wooNumber      String
  stage          String          // received | accepted | ready | out | delivered | cancelled
  prepMinutes    Int?            // מה שהמטבח הבטיח
  promisedAt     DateTime?       // מחושב ברגע האישור — מכאן נמדד איחור
  fulfillment    String          // delivery | pickup
  courierId      String?
  customerName   String
  customerPhone  String?
  address        String?
  total          Decimal
  items          Json
  placedAt       DateTime
  syncedAt       DateTime @updatedAt
  lastError      String?

  @@unique([tenantId, wooOrderId])
  @@index([tenantId, stage, placedAt])
}

model WooOrderEvent {          // מי עשה מה ומתי
  id        String   @id @default(cuid())
  orderId   String
  stage     String
  actorId   String?
  actorName String
  at        DateTime @default(now())
}
```

`@@unique([tenantId, wooOrderId])` הופך את הקליטה לאידמפוטנטית: אותו webhook שיישלח שלוש פעמים ייצור רשומה אחת.

`promisedAt` הוא מה שמאפשר למדוד ביצועים — כמה הזמנות יצאו בזמן, ואיפה נשבר.

## 6. איך המידע זורם

**הזמנה נכנסת:** WooCommerce → webhook חתום ב-HMAC → TOP ALENA → התראה + צליל באייפד.

**שינוי שלב:** TOP ALENA → `PUT /wp-json/wc/v3/orders/{id}` → הלקוח רואה בדף התודה (שכבר מרענן את עצמו כל 90 שניות).

## 7. כשהחיבור נופל — לא אופציונלי

1. **ניסיון חוזר** של WooCommerce.
2. **השלמה כל 5 דקות** — TOP ALENA מושכת את הזמנות 24 השעות האחרונות ומשווה. כל מה שה-webhook פספס נקלט. **זו רשת הביטחון האמיתית.**
3. **תור יוצא** — שינוי שנכשל נשמר ונשלח שוב, והמסך מציג **"ממתין לסנכרון"** ולא ✓ ירוק.

הכלל: **המצב באתר הוא האמת** לגבי הכסף; **המצב אצלנו הוא האמת** לגבי התפעול.

## 8. אבטחה

- Webhook חתום ב-HMAC, המפתח בצד השרת בלבד
- מפתחות WooCommerce REST בהרשאת **הזמנות בלבד**
- הרשאות לפי דרגות ה-RBAC הקיימות
- **שום מפתח לא נכנס לקוד או ל-git — ההזנה שלך**

## 10. הוכרע (2026-08-17)

**זמני הכנה:** 10 · 15 · 20 · 30 · 45 · 60 דקות, ואפשרות להקליד מספר חופשי.

**השליחים חיצוניים — אינם משתמשים במערכת.** לכן "נמסר" אינו מסך מזוהה אלא **קישור אישי לכל הזמנה**:

- טוקן אקראי ארוך, **לכל הזמנה בנפרד** — קישור אחד לא חושף אף הזמנה אחרת
- **פג תוקף** כמה שעות אחרי המסירה, ומת עם סגירת ההזמנה
- מציג רק את **מה שדרוש כדי למסור**: שם, כתובת, טלפון, מה בהזמנה — ולא היסטוריה, לא מחירים של אחרים, ולא ניווט לשום מקום אחר במערכת
- כפתור אחד: **נמסר**
- הקישור נשלח לשליח בוואטסאפ כשההזמנה יוצאת

זו הנקודה הרגישה באיפיון: **קישור בלי סיסמה שמכיל כתובת וטלפון של לקוח.** לכן הוא צר, קצר-חיים, ומוגבל להזמנה אחת. בלי המגבלות האלה הוא הופך לדלת אחורית לנתוני לקוחות.

**חריגה מהזמן שהובטח:** צבע במטבח **תמיד**. הודעה ללקוח — **כפתור, לא אוטומט**: מישהו במטבח מחליט לשלוח "מתעכבים, עוד ~10 דקות". הודעת איחור אוטומטית מגיעה בדיוק כשהמטבח עמוס מכדי לתקן אותה, והופכת לקוח שלא שם לב לאיחור ללקוח שכועס.
