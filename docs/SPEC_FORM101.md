## 0. ממצא שמשנה את התכנון — לקרוא לפני הכל

לרשות המסים יש **"כללים והוראות להפקת טופס 101 אלקטרוני"** (מכוח תקנה 2(ה) לתקנות
המשכורת). עיקרי הדרישות:

| דרישה | מה זה אומר לנו |
|---|---|
| כניסה למערכת ע"י העובד ב**סיסמה אישית המבטיחה זיהוי חד-חד ערכי** | ❌ **קישור ציבורי עם טוקן לא עומד בזה.** זה מפיל את התבנית של `EventContractSign` כפי שהיא |
| "חתימת" העובד = **הזנה חוזרת של הסיסמה**, ואז הטופס **ננעל** לעריכה | הציור באצבע נשאר כראיה ויזואלית, אבל הנעילה + הזיהוי הם מה שנותן תוקף |
| המעסיק חותם ב**חתימה אלקטרונית מאושרת** (חוק חתימה אלקטרונית) | דורש תעודה/שירות חיצוני. **לא בהיקף v1** — ראה §9 |
| **העברת נתונים משנה לשנה** (חלקים ב׳, ג׳, ו׳) + אישור אקטיבי של העובד שהם נכונים | מחייב מודל "שנת מס", לא רשומה אחת לנצח |
| **ארכיון ממוחשב עם שמירת כל הגרסאות הקודמות** ויכולת אחזור | טבלת גרסאות, לא UPDATE במקום |
| שדות חובה חוסמים סיום; צירוף מסמכים נדרש חוסם סיום | ולידציה חוסמת |
| **המערכת חייבת להיות מאושרת ע"י רשות המסים** | ⚠️ ראה למטה |

### מה נבנה בעקבות זה (הוכרע)

**1. שני מסלולי כניסה.**
- **מזוהה (ברירת מחדל):** `/Form101` **מאחורי `AuthProvider`**. העובד נכנס עם החשבון
  שכבר יש לו (זמינות, משמרות), מזוהה חד-חד ערכית. `identified=true`.
- **טוקן (חלופי):** `/Form101Sign?token=` **ציבורי**, לעובד חדש שעוד אין לו חשבון.
  `identified=false`.

**2. ⚠️ ההבדל בין השניים חייב להיות גלוי, לא מוסתר.** `form_data.identified` נשמר על
הרשומה; בכרטיס העובד ובמסך "מי לא מילא" מוצג תג **"מולא ללא זיהוי"** על טפסים
במסלול הטוקן, עם פעולת "בקש מילוי מחדש אחרי פתיחת חשבון". בלי זה נוצר מצב שבו נראה
שיש 101 תקין לכולם בזמן שחלקם לא עומדים בדרישה — וזה בדיוק מה שיתפוצץ מול פקיד שומה.
הטוקן חד-פעמי, פג תוך 14 יום, ונשרף בנעילה.

**3. אישור רשות המסים למערכת — הוכרע: מסלול א׳.**
המשמעות המעשית: עד שהמערכת מאושרת, הטופס הדיגיטלי הוא **מסמך פנימי מצוין** (כל
המידע, חתום, מתוארך, נשמר, ניתן להדפסה) אבל **הוא לא מחליף רשמית את הטופס מול פקיד
השומה**. שתי דרכים לחיות עם זה:
- **מסלול א׳ (מומלץ ל-v1):** בונים את הכל; העובד ממלא וחותם דיגיטלית; **מפיקים PDF
  בפריסה הרשמית שנשמר בכרטיס**. רו"ח שלך מאשר את הנוהל. זה מה שרוב העסקים הקטנים
  עושים בפועל.
- **מסלול ב׳:** מגישים בקשת אישור מערכת לרשות המסים (יש שירות ייעודי ב-gov.il;
  מפתחים נדרשים לבקש עד 4 חודשים לפני תום שנת המס). זה מסלול רגולטורי, לא ספרינט.

⚠️ **אני לא הסמכות כאן. המפרט הזה חייב לעבור את רו"ח שלך לפני שהוא מגיע לעובד אמיתי.**


### ⚠️ מלכודת האינדקס — הדבר הכי מסוכן כאן
קיים היום `CREATE UNIQUE INDEX "EmployeeForm_emp_type" ON ("employee_id","form_type")`.
**הוא מונע רשומה שנייה לאותו עובד לאותו טופס — כלומר מונע חידוש שנתי.**
סדר הפעולות בסקריפט הוא קריטי:
```sql
-- 1. עמודה
ALTER TABLE "EmployeeForm" ADD COLUMN IF NOT EXISTS "tax_year" INTEGER;
-- 2. backfill — בלי זה NULL-ים נחשבים ייחודיים והאינדקס החדש חסר ערך
UPDATE "EmployeeForm" SET "tax_year" = 0 WHERE "tax_year" IS NULL;
ALTER TABLE "EmployeeForm" ALTER COLUMN "tax_year" SET DEFAULT 0;
-- 3. אינדקס חדש
CREATE UNIQUE INDEX IF NOT EXISTS "EmployeeForm_emp_type_year"
  ON "EmployeeForm" ("employee_id","form_type","tax_year");
-- 4. ורק עכשיו מפילים את הישן
DROP INDEX IF EXISTS "EmployeeForm_emp_type";
```
`tax_year=0` = "רשומה היסטורית/לא-שנתית" (הסכם עבודה, בטיחות, וכל 101 ידני שקיים היום).
**`setEmployeeForm` הקיים (`load.ts` ~9345) חייב להתעדכן להיות מודע ל-tax_year** — אחרת
ה-`SELECT ... WHERE employee_id AND form_type LIMIT 1` שלו ידרוס את הרשומה ההיסטורית.

### טבלת גרסאות (דרישת "שמירת כל הגרסאות")
```sql
CREATE TABLE IF NOT EXISTS "EmployeeFormVersion" (
  "id" TEXT PRIMARY KEY, "form_id" TEXT NOT NULL, "employee_id" TEXT NOT NULL,
  "tax_year" INTEGER, "form_data" JSONB, "reason" TEXT,   -- submit|change|correction
  "created_at" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX IF NOT EXISTS "EmployeeFormVersion_form" ON "EmployeeFormVersion" ("form_id");
```
כל submit/שינוי כותב snapshot. שום דבר לא נמחק.

### כל השאר יושב ב-`form_data` (JSONB)
לא יוצרים 60 עמודות. סכימת ה-JSON ב-§2.

## 3. מסכים

### 3.1 `/Form101` — העובד ממלא (מובייל-first, RTL)
- **מאחורי `AuthProvider`** (לא ציבורי — §0).
- **אשף בשלבים** לפי חלקי הטופס: פרטים אישיים → בן/בת זוג → ילדים → הכנסה כאן →
  הכנסות אחרות → זיכויים → תיאום מס → הצהרה וחתימה. פס התקדמות.
- **טיוטה נשמרת אוטומטית** בכל מעבר שלב (`status='draft'`).
- **שנה שנייה ואילך:** חלקים ב׳/ג׳/ו׳ מגיעים **מלאים מראש** מהשנה הקודמת, עם מסך
  "האם הפרטים עדיין נכונים?" ואישור אקטיבי — זו דרישה מפורשת בכללים.
- **חתימה:** קנבס ציור אצבע (מועתק מ-`EventContractSign.jsx`), + תיבת "אני מצהיר/ה
  שהפרטים מלאים ונכונים" עם הנוסח הרשמי. שליחה → `status='locked'`, הטופס ננעל.
- אחרי נעילה: תצוגה בלבד + כפתור "בקשת תיקון" שפותח שורה בחלק ז׳ (ולא דורס).

### 3.2 בכרטיס העובד (`Employee360.jsx`)
- שורת 101 מציגה **סטטוס לשנת המס הנוכחית**: לא נשלח / נשלח / טיוטה / נחתם ✓.
- צפייה בטופס המלא כפי שמולא, **הורדת PDF**, והיסטוריית שנים קודמות.
- ההתראה הקיימת (`load.ts` ~9665) משתנה מ-"אין 101" ל-"אין 101 **לשנת המס הנוכחית**".

### 3.3 מסך מנהל — "מי עוד לא מילא"
טבלה של כל העובדים הפעילים מול סטטוס 101 לשנה הנוכחית + "שלח תזכורת לכולם".

## 4. פונקציות API

| פונקציה | מי | תפקיד |
|---|---|---|
| `getMyForm101({tax_year})` | העובד המחובר | טיוטה/נעול + prefill מהשנה הקודמת + פרטי המעביד |
| `saveMyForm101Draft({tax_year, form_data})` | העובד | שמירת טיוטה (חסום אם נעול) |
| `submitMyForm101({tax_year, form_data, signature_data_url})` | העובד | ולידציה מלאה → snapshot לגרסאות → `locked` + IP + user-agent |
| `getEmployeeForm101({employee_id, tax_year})` | back-office | צפייה מנהלית |
| `listForm101Status({tax_year})` | back-office | מסך "מי לא מילא" |
| `sendForm101Request({employee_id[], tax_year})` | back-office | וואטסאפ + תזכורות |

כולן דרך `requireBackOffice` פרט לשלוש הראשונות, שנשענות על `user` המחובר ומסננות
**רק את העובד עצמו** — לא לקבל `employee_id` מהלקוח בפונקציות העובד.

## 5. ה-PDF

**ממצא: אין ספריית PDF בצד השרת.** בפרונט כבר יש `jspdf@4` + `html2canvas@1.4`.
להוסיף Chromium/puppeteer לקונטיינר זו התנפחות משמעותית **לכל הטננטים**.

**הוכרע: הפקה בצד הלקוח + שמירה אוטומטית בכל חתימה.**
מרנדרים את הטופס בפריסה הרשמית כ-HTML (עברית RTL עובדת מושלם בדפדפן),
`html2canvas` → `jspdf`. **ברגע הנעילה** הקובץ נוצר בדפדפן של העובד, נשמר ל-`file_url`
ומופיע בתיקיית המסמכים של העובד כסוג `'101'`. שורת התוקף מודפסת בתחתית:
> *נחתם דיגיטלית בתאריך {תאריך} בשעה {שעה} מכתובת IP {ip} · מזהה טופס {id}*

**המקור המחייב נשאר ה-JSON + החתימה במסד** — ה-PDF הוא ההעתק השמור. ניתן להפיק
מחדש בכל רגע מהרשומה.

⚠️ **פרט מימוש לפתור בסבב ב׳:** `UploadFile` הקיים פונה ל-`/integrations/upload-file`
עם JWT. **במסלול הטוקן אין JWT** — לכן `submitForm101ByToken` יקבל `pdf_base64` בגוף
הבקשה ויכתוב בעצמו לאותו נתיב אחסון. לבדוק את מגבלת גודל הגוף (PDF ~200–500KB
ב-base64) לפני שסוגרים את זה.
